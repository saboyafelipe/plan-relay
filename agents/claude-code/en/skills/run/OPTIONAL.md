# Optional pieces

Four pieces not every environment has. Missing one does not stop the run; it goes into the briefing with the sentence below and into the journal header.

- **5-hour window** — `window.sh --read` gave `status=off`, `no-data`, `timeout` or `unknown-format`, or the owner chose "turn off": "The autopilot runs without the 5-hour window gate: it does not stop when the subscription quota reaches the threshold, and a limit hit shows up as worker failures." On `off`, add: "The probe ships off; to turn it on, set `PLAN_RELAY_WINDOW=on` in the session environment (in VS Code, the Plan Relay panel's ⋯ menu item '5-hour window gate…' writes it for the project) and open a new session." On `unknown-format`, add: "The probe answered in a format `window.sh` does not recognize; I recommend turning it off (remove `PLAN_RELAY_WINDOW=on` from the environment), because each probe spends quota without giving data." With `no-subscription`, the sentence is another: "The session does not pay through the Claude subscription (`ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN` or `ANTHROPIC_API_KEY` is in the environment; in the VS Code Agents window, the account is Copilot's): `window.sh` does not probe, and the autopilot runs without the 5-hour window gate." With `off`, `no-subscription`, `unknown-format` or "turn off", the conductor does not call `window.sh` again in this run; with `no-data` or `timeout`, the gate keeps trying, because the failure may be transient (network, login).
- **Permissions** — this session's context does not say "auto mode is active": "This session is not in auto mode: each worker command without a saved permission rule waits for a card nobody answers, or is refused with no card (in the VS Code Agents window). For the autopilot to get to the end, put the session in auto mode (in the Agents window, "Auto Mode" in the permission picker) or save rules for the plan's commands, and run `{{AGENT_PLUGIN_SKILL_PREFIX}}run <folder>` again." With the owner present in the preflight, the run may go on; the sentence goes into the briefing as a concrete action.
- **Notification** — without the `PushNotification` tool (`ToolSearch` does not find it): "Warnings to the owner stay only in the journal and in the final message; nothing reaches outside this session."
- **Plugin check through the CLI** — in `check.sh`, `agent-cli` with status `missing` or `plugin` with status `unknown`: "It was not possible to check whether the context hook is active; without it, the conductor gets no limit warning and the handoff depends on the owner saying "stop"." With `plugin` at `missing` or `warning`, the briefing shows the `detail`, which says how to install or enable it.
